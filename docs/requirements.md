# 功能与需求

## 1. 产品边界

只开发通用提醒功能。截图用于理解需要支持的频率与时间表达，不作为内置提醒、种子数据或专用模板。所有事项均由用户安装后自行创建。

- 首次启动提醒列表为空，显示“添加提醒”入口，不自动生成或启用任何事项。
- 用户自行输入名称、备注、分类及时间规则；不需要在开发前提交个人事项清单。
- 创建流程按规则要求校验必要字段，并预览未来几次触发时间。
- 用户可保存自己创建的提醒并复制复用；软件不预填截图中的名称、次数、剂量或时间。

界面提供明确的时间和周期选择。“早晚”等描述需由用户设置为具体时间；相对日程需由用户创建参照时间并填写偏移量。规则校验与解释在软件内完成，不依赖开发者逐项确认。

## 2. 第一版功能

### 提醒管理

- 创建、编辑、复制、暂停、恢复、归档提醒；分类可自定义，未分类事项归入“未分类”。
- 字段包括名称、备注、可选数量/单位、开始日期、可选结束日期、重复规则及每日多个时间点。
- 支持单次、每天、每周指定星期、每 N 个日历日；每周可选多个星期。
- 每 N 天规则必须显式选择起算日期，并预览未来几次日期。“每隔 2 天”在界面直接显示为“每 2 个日历日一次，例如 1 日、3 日、5 日”，避免歧义。
- 支持用户配置简单周期序列，例如间隔 2、3 天交替；保存前预览日期并由用户确认，不将范围描述解释成随机间隔。
- 支持相对固定日程：参照日程名称、时刻和提前或延后分钟数均由用户填写。修改参照日程时，展示受影响的提醒。
- 允许只修改某一次，或从指定日期起修改后续安排；以往记录保留。

### 收到提醒后的处理

- 系统通知显示事项、计划时间和可选备注，支持声音、振动；受系统通知渠道设置限制的选项提供设置入口。
- 从通知或 App 内标记“已完成”“稍后提醒”“跳过本次”。“已完成”由用户主动确认，通知送达不等于已完成。
- 稍后提醒提供可配置预设和自定义时长，仅影响当前这次安排。
- 可选未确认后的再次提示，须配置间隔、上限和停止时间；完成、跳过、暂停后立即停止后续提示。
- 未确认事项进入待处理列表，不自动改变原有周期。锁屏可隐藏事项名称及备注，仅显示“有一项提醒”。

### 页面

1. 今日：按时间排列待办、已完成及待处理事项，突出下一条提醒。
2. 提醒管理：按分类筛选，快速编辑、复制、暂停。
3. 新建/编辑：内容 → 频率与时间 → 提示方式 → 日期预览；复杂选项默认收起。
4. 历史：查看每次计划时间、完成时间、跳过、稍后提醒及手动补记；支持修正并保留变更痕迹。
5. 设置与提醒检查：权限、系统通知渠道、后台限制、测试提醒、备份恢复与显示隐私。

### 数据与可靠性

- 离线存储；不强制登录，不上传提醒内容与记录，不接入广告与第三方行为分析。
- 支持通过系统文件选择器导出/导入备份；导出前说明包含提醒和记录，导入先预览并确认，第一版采用有备份保护的整体恢复，不静默合并。
- 开机、应用更新、时间/时区变化后重建后续提醒；错过的事项进入待处理，不密集弹出过期通知。
- 提醒能力检查覆盖通知权限、精确闹钟访问、通知渠道和后台限制；无法直接检测的项目提示用户检查，不显示虚假的“全部正常”。

## 3. 后续扩展

以下属于后续版本，第一版保留数据和规则扩展位置，不同时铺开。

- 更复杂的阶段计划：某段时间每日，另一段时间改为每周；按实际完成时间计算下一次的规则需独立选择，不混同固定日历计划。
- 临时停用时间段、工作日/节假日、旅行时区策略。
- 桌面组件、日历视图、趋势统计、库存与补充提醒。
- 加密备份、可选跨设备同步与家庭协作。同步前需选定“两台手机各自提醒”还是“共享同一份完成状态”，以及是否需要指定一台主提醒设备。
- 用户自建模板导入导出；相对实际事件的提醒，例如用户记录某个事件的发生时间后再计算安排。

## 4. 配置与适配边界

个人提醒的名称、具体时间、起始日期、周期、参照日程及提示方式全部在 App 内设置，不是开发前置条件。

- 第一版两台设备各自独立使用，不要求说明使用人或提供个人数据；需要同步时再确定共享方式。
- 普通通知、声音、振动及有限次数的再次提示由用户选择；全屏闹钟属于另行评估功能。
- 真机验收时记录两台设备的实际型号、Android 和 HyperOS 版本；具体提醒内容不影响适配范围。
