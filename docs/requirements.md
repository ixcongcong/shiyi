# 功能与需求

## 1. 当前需求

以用户截图为需求来源。名称暂按截图转录，保存前可以修改。以下都只是待配置模板，不自动启用，也不填入猜测的服用时间或剂量。

| 事项 | 截图要求 | 规则表达 | 开发前待确认 |
| --- | --- | --- | --- |
| 叶酸 | 每天提醒 | 每日 + 一个或多个时间点 | 具体时间 |
| 胆维丁 / 维生素 D | 每隔 2–3 天 | 明确的间隔天数；如确有需要，支持 2、3 天交替周期 | 药品名称；究竟每 2 天、每 3 天还是交替；起算日期 |
| 沃卵宝 | 早晚两次 | 每日 + 早、晚两个独立时间点 | 名称、早晚时间 |
| 锻炼 | 每晚 | 每日 + 晚间时间点 | 提醒时间；是否需要记录时长 |
| 优甲乐 | 早上饭前 | 每日 + 早间时间点 + 饭前备注；可选相对早餐的提醒 | 早餐参照时间，以及所需提前量；不预设医学间隔 |
| 中药 | 每天两次 | 每日 + 两个独立时间点 | 两次具体时间及备注 |

“早晚”“饭前”不是设备可直接执行的时刻，须由用户配置时间或明确的时间参照。提醒工具按用户确认的安排执行，不自动生成剂量、药物间隔或补服安排。

## 2. 第一版功能

### 提醒管理

- 创建、编辑、复制、暂停、恢复、归档提醒；分类可自定义，初始提供用药、补充剂、运动、其他。
- 字段包括名称、备注、可选数量/单位、开始日期、可选结束日期、重复规则及每日多个时间点。
- 支持单次、每天、每周指定星期、每 N 个日历日；每周可选多个星期。
- 每 N 天规则必须显式选择起算日期，并预览未来几次日期。“每隔 2 天”在界面直接显示为“每 2 个日历日一次，例如 1 日、3 日、5 日”，避免歧义。
- 支持简单周期序列，例如间隔 2、3 天交替；保存前预览日期并由用户确认，不把“2–3 天”解释成随机间隔。
- 支持相对固定日程：例如早餐 08:00、提前 X 分钟提醒；提前量由用户填写。修改早餐时间时，展示受影响的提醒。
- 允许只修改某一次，或从指定日期起修改后续安排；以往记录保留。

### 收到提醒后的处理

- 系统通知显示事项、计划时间和可选备注，支持声音、振动；受系统通知渠道设置限制的选项提供设置入口。
- 从通知或 App 内标记“已完成”“稍后提醒”“跳过本次”。“已完成”由用户主动确认，通知送达不等于已完成。
- 稍后提醒提供可配置预设和自定义时长，仅影响当前这次安排。
- 可选未确认后的再次提示，须配置间隔、上限和停止时间；完成、跳过、暂停后立即停止后续提示。
- 不根据漏记自动要求补服。锁屏可隐藏药名及备注，仅显示“有一项提醒”。

### 页面

1. 今日：按时间排列待办、已完成及待处理事项，突出下一条提醒。
2. 提醒管理：按分类筛选，快速编辑、复制、暂停。
3. 新建/编辑：内容 → 频率与时间 → 提示方式 → 日期预览；复杂选项默认收起。
4. 历史：查看每次计划时间、完成时间、跳过、稍后提醒及手动补记；支持修正并保留变更痕迹。
5. 设置与提醒检查：权限、系统通知渠道、后台限制、测试提醒、备份恢复与显示隐私。

### 数据与可靠性

- 离线存储；不强制登录，不上传健康信息，不接入广告与第三方行为分析。
- 支持通过系统文件选择器导出/导入备份；导出前说明包含提醒和记录，导入先预览并确认，第一版采用有备份保护的整体恢复，不静默合并。
- 开机、应用更新、时间/时区变化后重建后续提醒；错过的事项进入待处理，不密集弹出过期通知。
- 提醒能力检查覆盖通知权限、精确闹钟访问、通知渠道和后台限制；无法直接检测的项目提示用户检查，不显示虚假的“全部正常”。

## 3. 后续扩展

以下属于后续版本，第一版保留数据和规则扩展位置，不同时铺开。

- 更复杂的阶段计划：某段时间每日，另一段时间改为每周；按实际完成时间计算下一次的规则需独立选择，不混同固定日历计划。
- 临时停用时间段、工作日/节假日、旅行时区策略。
- 桌面组件、日历视图、趋势统计、库存与补充提醒。
- 加密备份、可选跨设备同步与家庭协作。同步前需选定“两台手机各自提醒”还是“共享同一份完成状态”，以及是否需要指定一台主提醒设备。
- 自定义模板导入导出；相对实际事件的提醒，例如用户确认早餐时间后再计算安排。

## 4. 待确认事项

这些问题不影响先确认产品范围和建立仓库，但影响默认模板与最终真机验收。

1. 每项的具体时间、药品名称，以及维生素 D 的间隔和起始日期。
2. 早餐是大致固定时间，还是每天变化；饭前提醒采用固定时刻还是相对日程。
3. 普通通知是否足够，是否需要用户开启更强的声音和重复提示。全屏闹钟属于另行评估功能，不能保证具备系统权限。
4. 两台设备分别给不同的人使用，还是同一个人使用；是否需要同步。
5. 两台设备“关于手机”中的型号、Android 版本和 HyperOS 版本；最后以实机行为为准。
